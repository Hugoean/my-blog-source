RedPajama: an Open Dataset for Training Large

轨道 A 优先级 read W6 CPTMultilingual 原文 ↗ PDF ↗
📝 论文一图速览(Claude Opus 4.7 填写)

一句话总结:RedPajama-V2 = 30T 去重 tokens(总 100T+ 原始 tokens)的多语种 web 语料(英/德/法/西/意),覆盖 84 个 CommonCrawl dumps(2014-2023),并为每篇文档预计算 40+ 种 quality signals 作为元数据——把"是否过滤"这件事推迟给下游用户,使 C4 / Gopher / RefinedWeb / FineWeb 等过滤组合都能作为 RPv2 的特例复现出来。

🎯 面试考点(高频):

  1. 数据来源(必背):84 个 CommonCrawl 的 .wet snapshots(2014 至 2023-04),全部走 CCNet 流水线:5-gram Kneser-Ney 在 Wikipedia 上训得的困惑度把文档切成 head / middle / tail 三桶;RPv2 三桶全留(RPv1 只留 head+middle)。CCNet 在每个 dump 内分片内做去重。共得 113B docs / 100T+ tokens;去重后 head+middle ≈ 30.4T tokens。
  2. 5 类 quality signals(40+ 项):
    • Natural Language(自然语言度):全大写词比例、行末省略号比例、unique-word 比例、行末终止标点等。
    • Repetitiveness(重复度):top n-gram($n\in\{2,3,4\}$)字符占比 + 重复 n-gram($n\in\{5,\ldots,10\}$)字符占比。
    • Content-based(内容):LDNOOBW 黑词命中数 + UT1 黑域名命中标志(NSFW 过滤)。
    • ML Heuristics(机器学习):fastText 一元分类器(高质域 vs RPv2 原始)+ DSIR importance weight(log-likelihood 比);英文目标域用 Wiki / Wiki-Ref / books / OpenWebText,非英文只用 Wiki。
    • Deduplication(去重):MinHash LSH 模糊去重 + Bloom filter(1% 错误率)精确去重;按时间倒序逐 dump 累积。
  3. vs RPv1 / Pile / RefinedWeb / FineWeb:
    • RPv1:1.2T tokens,7 个域(CC + C4 + GitHub + Books + ArXiv + Wiki + StackExchange)复刻 LLaMA-1 配方;composite, 英文为主。
    • Pile:0.8 TB composite,英文,22 个高质域,常作 PPL 评测集。
    • RefinedWeb / FineWeb:web-only,作者已把过滤烧死在数据集里,用户只能用作者的滤镜。
    • RPv2:web-only、多语种、raw + signals 出货,过滤组合在下游自由拼;100T+ tokens 是目前最大开放预训练数据集。
  4. 多语种覆盖:EN / DE / FR / ES / IT(没有中日韩);各语种 token 比例 ≈ 73 : 10 : 8.5 : 9.5 : 4.7(原始 T 数),head+middle 去重后比例类似。设计上偏欧洲语言,因为 CCNet 流水线对这五种语言有成熟的 sentence-piece 与 KN-LM。
  5. 过滤组合性(论文的核心实验结论):在 468M LM / 100B tokens 与 1.6B LM / 350B tokens 上扫了 18 种过滤组合,核心结论:
    • Gopher-rules + fuzzy dedup(MinHash LSH)聚合 benchmark 最强,只输 RefinedWeb 平均分但 rank-score 反超。
    • Gopher-natlang 比 Gopher-repetition 更有用。
    • fastText 与 DSIR 差距不显著(选实现更轻的 fastText)。
    • 单独 C4 line-filter 只降 PPL,不动 benchmark 平均。
    • 未过滤的 RPv2 在 Paloma 上 PPL 反而最低 → Paloma 域分布广,过度过滤会偏离它。
  6. 已知坑 / 局限:① ablation 全在 ≤1.6B,大规模未验;② 没做 benchmark 去污染分析;③ 没做 PII 分析;④ ML 滤镜可能放大对少数群体的偏差(论文显式提及)。
  7. 生态足迹:Snowflake Arctic、Salesforce XGen、AI2 OLMo、OpenELM、RedPajama-INCITE-3B/7B 都用过 RP 数据;SlimPajama = 进一步清洗去重的 RPv1。

Figure 1: The ecosystem around the RedPajama datasets. RedPajama has provided pretraining data

① 图说明:RedPajama-V2 数据处理流水线全图(横向 4225×1430)。从左到右:84 个 CommonCrawl .wet dumps → CCNet(分片去重 + Wikipedia KN-LM 困惑度三桶切分 head/middle/tail)→ 5 语种切分(EN/DE/FR/ES/IT)→ 40+ Quality Signals(自然语言度、重复度、内容、ML、去重)→ MinHash LSH 模糊去重 + Bloom filter 精确去重 → 最终带元数据的语料。

② 关键数据:84 dumps(2014 至 2023-04);CCNet 默认输出 113B 文档;head+middle 共 32.8B 文档(50.7T tokens),tail 80.5B 文档(73.0T tokens);去重后 head+middle 还剩 20.8B 文档 / 30.4T tokens(论文 Table 3)。Bloom filter 错误率 1%;MinHash LSH 用 word 13-gram + 128 hash / 9 bands / 13 rows。

③ 启示:读图要看清"raw + signals"这一关键设计:论文没有把过滤逻辑 hardcode 进数据,而是把每个 signal 作为列挂在文档上,下游用 SQL-like 阈值组合即可还原出 C4 / Gopher / RefinedWeb 等不同过滤方案。这是 RPv2 与同时代 web 数据集(RefinedWeb / FineWeb 把过滤烧死)最本质的差别,也是它能成为"过滤研究试验田"的根本原因。

① 图说明:RPv2 在 84 个 CommonCrawl dumps 上的重复率分布(p.19,附录配图)。横轴为 dump 时间序号(从最新 2023-14 倒序到 2014-15),纵轴为该 dump 中被精确去重 / 模糊去重的文档比例。重复检测顺序:先 dump 自身内,再与所有后续(更新) dumps 比对。

RedPajama: an Open Dataset for Training Large Language Models Maurice Weber1, Daniel Y. Fu1,2, Quentin Anthony4,8,10, Yonatan Oren1 Shane Adams1, Anton Alexandrov7,, Xiaozhong Lyu7, Huu Nguyen5, Xiaozhe Yao7, Virginia Adams1, Ben Athiwaratkun1, Rahul Chalamala1,11, Kezhen Chen1, Max Ryabinin1 Tri Dao1,6, Percy Liang1,2, Christopher Ré1,2, Irina Rish8,9, Ce Zhang1,3

Abstract / 摘要p.1

Large language models are increasingly becoming a cornerstone technology in artificial intelligence, the sciences, and society as a whole, yet the optimal strategies for dataset composition and filtering remain largely elusive. Many of the top-performing models lack transparency in their dataset curation and model development processes, posing an obstacle to the development of fully open language models. In this paper, we identify three core data-related challenges that must be addressed to advance open-source language models. These include (1) transparency in model development, including the data curation process, (2) access to large quantities of high-quality data, and (3) availability of artifacts and metadata for dataset curation and analysis.

To address these challenges, we release RedPajama-V1, an open reproduction of the LLaMA training dataset. In addition, we release RedPajama-V2, a massive web-only dataset consisting of raw, unfiltered text data together with quality signals and metadata. Together, the RedPajama datasets comprise over 100 trillion tokens spanning multiple domains and with their quality signals facilitate the filtering of data, aiming to inspire the development of numerous new datasets. To date, these datasets have already been used in the training of strong language models used in production, such as Snowflake Arctic, Salesforce's XGen and AI2's OLMo. To provide insight into the quality of RedPajama, we present a series of analyses and ablation studies with decoder-only language models with up to 1.6B parameters. Our findings demonstrate how quality signals for web data can be effectively leveraged to curate high-quality subsets of the dataset, underscoring the potential of RedPajama to advance the development of transparent and high-performing language models at scale.

大语言模型正日益成为人工智能、科学与社会的基石性技术,然而关于数据集构成与过滤的最优策略,仍在相当程度上未被揭示。许多表现最好的模型在数据整理与模型开发流程上缺乏透明度,妨碍了完全开放语言模型的发展。本文识别出推进开源语言模型必须解决的三大数据相关挑战:(1) 模型开发(含数据整理过程)的透明度;(2) 对大量高质量数据的可获得性;(3) 数据集整理与分析所需"产物 + 元数据"的可用性。

为应对这些挑战,我们发布 RedPajama-V1——LLaMA 训练数据的开源复刻;以及 RedPajama-V2——一个仅基于 web 的大规模数据集,由未经过滤的原始文本数据以及伴随的 quality signals 与元数据构成。两者合计超过 100 万亿 tokens,横跨多个领域,quality signals 便于做数据过滤,旨在催生出多样化的新数据集。截至目前,这些数据已被用于训练 Snowflake Arctic、Salesforce 的 XGen 与 AI2 的 OLMo 等生产级强模型。为揭示 RedPajama 的数据质量,我们在最大 1.6B 参数的 decoder-only 语言模型上做了一系列分析与消融研究。结果表明:web 数据的 quality signal 能被有效用于挑选出高质量子集,凸显了 RedPajama 在推动"透明且高性能的大规模语言模型"发展方面的潜力。

§1 Introduction / 引言 · 三大开源挑战p.1

Pretraining data is among the most central building blocks that go into the development of modern large language models (LLMs). However, one of the core challenges this field faces is the general lack of transparency regarding the composition and curation strategy of pretraining data. Indeed, with a few notable exceptions, the majority of reports documenting state-of-the-art LLMs provide scarce details, if any, on their pretraining datasets. Even open-weights models such as LLaMA provide little to no details about their training data, let alone release their datasets. Furthermore, the process of studying and building optimal data compositions, along with developing filtering rules and heuristics, is time-consuming as it necessitates running numerous ablations on different compositions of the training data.

预训练数据是现代大语言模型(LLM)开发中最核心的构建块之一。然而,本领域面临的核心挑战之一,是关于预训练数据组成与整理策略的普遍缺乏透明度。事实上,除少数显著例外,记录前沿 LLM 的多数报告几乎不披露任何预训练数据的细节;即便是 LLaMA 等开放权重模型,也几乎不给出训练数据细节,更别说公开数据集本身。此外,研究并构建最优数据组合、发展过滤规则与启发式的过程极其耗时——它需要在多种不同训练数据组合上跑大量消融。

To address these challenges, and with the overarching goal of democratizing the access to and development of open-source LLMs, we have released the RedPajama datasets, which in total consist of more than 100 trillion tokens of text data. With this goal in mind, we use the following design principles to guide our approach to creating open datasets. Transparency. We strive for maximal transparency from at least two angles: documenting and making all aspects of data curation publicly available, and striving for open and transparent datasets, which allows application developers and researchers alike to better understand and design language models. Scale. Large pools of accessible data are one of the core building blocks of the most powerful large language models, yet are hard to come by due to the large amount of resources and expertise required to build, curate and store them. Versatility. We aim to provide the community with datasets and artifacts for building state-of-the-art open language models by providing a versatile resource. Rather than prescribing what constitutes a high-quality dataset, we offer a broad, general-purpose corpus of web documents. Each document is tagged with quality signals, empowering users to make informed decisions based on their specific needs and criteria.

为应对这些挑战,并以"让开源 LLM 的获取与开发更民主化"为总目标,我们发布了 RedPajama 数据集——合计超过 100 万亿 tokens 的文本数据。围绕这一目标,我们用以下三条设计原则指导整个开放数据集的构建。透明度(Transparency)。至少从两个方面追求最大透明:一方面把数据整理的所有环节文档化并公开;另一方面给出开放透明的数据集,让应用开发者与研究者都能更好地理解并设计语言模型。规模(Scale)。大规模可获取数据是最强 LLM 的核心构件之一,但由于构建、整理、存储所需的资源与专业能力极高,这种数据并不易得。多用途(Versatility)。我们的目标是为社区提供构建 SOTA 开源 LM 所需的多用途资源——而非规定"什么是高质量数据集",我们提供一个广覆盖、通用目的的 web 文档语料,并为每篇文档标注 quality signals,让用户根据各自的需求与判据自行决策。

Following these principles, we have developed and made publicly available the RedPajama datasets for LLM pretraining. RedPajama-V1 is a publicly available, fully open, best-effort reproduction of the training data described in the LLaMA paper. Together with this dataset, we have developed the RedPajama-INCITE models, which include base, instruction-tuned, and chat models at the 3B and 7B scales. Based on the first set of learnings from these efforts, we have built the RedPajama-V2 dataset. This latter dataset takes an entirely different approach and focuses exclusively on web data. It consists of five languages, sourced from 84 Common Crawl snapshots ranging from 2014 to 2023. In addition to the raw text data, we also publish quality signals accompanying each document in a 50T token subset of the corpus, with the goal of fostering research towards a principled understanding of ways to filter web data.

遵循这些原则,我们开发并公开了用于 LLM 预训练的 RedPajama 数据集。RedPajama-V1 是 LLaMA 论文中训练数据的完全开放、尽力而为的复刻;基于该数据集,我们还训练了 RedPajama-INCITE 模型族——包含 3B / 7B 两档的 base / instruction-tuned / chat 三类模型。在第一阶段经验的基础上,我们构建了 RedPajama-V2。后者采取截然不同的思路——专注于 web 数据,涵盖 5 种语言,来自 2014 至 2023 共 84 个 Common Crawl snapshots。除了原始文本,我们还为其中 50T tokens 子集的每篇文档发布一组 quality signals,以推动"如何原则性地过滤 web 数据"的研究。

§2 Related Work / 开放预训练数据集对比p.3

Numerous efforts have focused on constructing pretraining datasets for large language models. While some of these datasets are curated from a mix of various sources, others are exclusively derived from web data. In the realm of web-only datasets, the C4 dataset was one of the first large-scale web datasets, comprising a 175B-token web corpus filtered down from CommonCrawl. C4 still remains a benchmark for web dataset quality. More recently, RefinedWeb and FineWeb have demonstrated that web-only data can yield strong models without the need for compositing multiple domains, and—similar to our work—also provide ample details on their data curation techniques. In contrast to these datasets, RedPajama-V2 is composed of 100 trillion tokens of raw, mostly unfiltered text. With its more than 40 quality signals for potential filtering, RedPajama-V2 promotes an entirely different approach and aims to set a new standard for future high-quality web datasets, providing a robust foundation for the next generation of high-quality web datasets. Of further great relevance are the Gopher rules, which have been central to many of the previously mentioned open pretraining datasets.

已有大量工作致力于为大语言模型构建预训练数据集。其中一些是由多源混合而来,另一些则完全源自 web 数据。在 web-only 数据集中,C4 是最早的大规模 web 数据集之一,从 CommonCrawl 过滤得到一份 175B token 的 web 语料,至今仍是 web 数据集质量的标杆。最近,RefinedWeb 与 FineWeb 表明仅靠 web 数据、无需多域混合,也能训出强模型,并与本文工作类似地提供了大量数据整理细节。与这些数据集不同,RedPajama-V2 由 100 万亿 tokens 的原始、基本未过滤的文本构成。借助 40+ 项可用于过滤的 quality signals,RedPajama-V2 推行一种截然不同的方案,旨在为下一代高质量 web 数据集设立新标杆,提供坚实基础。此外,Gopher 规则也极为相关,它构成了上述多个开放预训练数据集的核心。

Complementing web-only datasets, composite datasets introduce additional domains and enable broader coverage. Most notably, the Pile was one of the first fully open datasets. After the release of LLaMA, which used seven individual subsets and multiple domains, we published RedPajama-V1 as an open-source replication of the LLaMA recipe, which gained widespread adoption. Building on this, the SlimPajama dataset was derived from RedPajama-V1 by further cleaning and deduplication. Similarly, the Dolma dataset includes other specialized domains, such as cleaned versions of code datasets including The Stack, StarcoderData, as well as the ArXiv and StackExchange splits of RedPajama-V1. The Zyda dataset goes in a similar vein and further refines open datasets, including the SlimPajama dataset derived from RedPajama-V1. Finally, the ROOTS corpus is also among the core open datasets spanning multiple domains and languages.

作为 web-only 数据集的补充,复合(composite)数据集引入更多领域、覆盖面更广。最显著的是 Pile——最早的完全开放数据集之一。LLaMA 发布后(它用了 7 个子集、覆盖多个领域),我们发布 RedPajama-V1 作为 LLaMA 配方的开源复刻,获得了广泛采用。在此基础上,SlimPajama 通过进一步清洗与去重从 RedPajama-V1 派生而来。类似地,Dolma 引入了其他专用领域,如清洗版的代码数据集(The Stack、StarcoderData)以及 RedPajama-V1 的 ArXiv 与 StackExchange 切片。Zyda 走类似路线,进一步精炼包括 SlimPajama 在内的开放数据集。最后,ROOTS 语料是跨多领域、多语种的核心开放数据集之一。表 1 汇总了这些开放数据集在透明度、多用途与规模上的对比。

§3 RedPajama-V1 / LLaMA 训练数据复刻p.4

In our first iteration of the RedPajama datasets, our primary goal was to recreate the training data documented in the LLaMA technical report. To this end, we closely follow the descriptions of the original recipes. The LLaMA pretraining data are drawn from seven datasets: English CommonCrawl, C4, GitHub, Wikipedia, Books (Project Gutenberg and Books3), ArXiv, and Stack Exchange. Each of these datasets is given a short (approximately one-paragraph) description in the LLaMA technical report, with some gaps. Table 2 summarizes the resulting token counts: CommonCrawl 878B, C4 175B, GitHub 59B, Books 26B, ArXiv 28B, Wikipedia 24B, StackExchange 20B—total 1.2T tokens.

RedPajama 数据集的第一次迭代,主要目标是重建 LLaMA 技术报告中所记录的训练数据。为此我们尽量贴合原始配方的描述。LLaMA 的预训练数据来自 7 个子集:英文 CommonCrawl、C4、GitHub、Wikipedia、Books(Project Gutenberg + Books3)、ArXiv、Stack Exchange。LLaMA 技术报告对每个子集只给出大约一段的描述,且有若干缺口。表 2 汇总最终 token 计数:CommonCrawl 878B、C4 175B、GitHub 59B、Books 26B、ArXiv 28B、Wikipedia 24B、StackExchange 20B,合计 1.2T tokens。

CommonCrawl. The LLaMA corpus includes five CommonCrawl snapshots from 2017 to 2020, processed using the CCNet pipeline. CCNet deduplicates each snapshot in shards and assigns a quality classification—"head," "middle," or "tail"—based on the distribution of perplexity assigned by a 5-gram Kneser-Ney model trained on Wikipedia. Here we only keep the "head" and "middle" buckets and discard the "tail." Touvron et al. also use a linear classifier trained on Wikipedia reference articles to filter out low-quality documents. The LLaMA paper does not specify which snapshots were used or give details on the classifier. We select the five English CommonCrawl snapshots 2019-30, 2020-05, 2021-04, 2022-5 and 2023-06, train a unigram fastText classifier on Wikipedia references (38M URLs, 300K crawled pages), and filter out all documents with score below 0.25.

CommonCrawl。LLaMA 语料用了 5 个 CommonCrawl snapshots(2017–2020),经 CCNet 流水线处理。CCNet 在每个 snapshot 内分片去重,并用一个在 Wikipedia 上训练的 5-gram Kneser-Ney 模型按困惑度分布给文档贴 head / middle / tail 三档质量。我们只保留 head 与 middle,丢弃 tail。Touvron 等人还用一个"Wiki-Ref"线性分类器过滤低质文档,但 LLaMA 论文未明确给出 snapshot 或分类器细节。我们选取 2019-30、2020-05、2021-04、2022-5、2023-06 五份 snapshot,从 Wikipedia 抽 38M URL、抓 300K 网页,用 fastText 训一元分类器,阈值 0.25 过滤。

C4 / GitHub / Wikipedia / Books / ArXiv / Stack Exchange. For C4 we use Allen AI's c4_en. GitHub keeps Apache/BSD/MIT-licensed projects on Google BigQuery, removing low-quality files by heuristics on length, alphanumeric ratio and file extension. Wikipedia uses the 2023-03-20 dump. Books: only the PG19 subset of Gutenberg (Books3 was originally included but later removed due to copyright). ArXiv keeps only LaTeX sources, removes preambles, comments and bibliography, and expands macros. Stack Exchange takes the 28 largest sites, removes HTML tags, and orders answers by score.

To evaluate how well RedPajama-V1 matches the original LLaMA corpus, we trained the RedPajama-INCITE family of LLMs (3B and 7B, base + instruction-tuned) on the Summit supercomputer at Oak Ridge National Lab (4608 6×V100 nodes, IBM Power9). Critically, V100s do not support bf16, so we had to train with fp16 + loss scaling and lower learning rates ($1.6\times10^{-4}$ for the 3B and $1.2\times10^{-4}$ for the 7B); we used 12-way pipeline parallelism for the 7B and 6-way for the 3B, plus 2-way tensor parallelism. We trained the 3B for 800B tokens and the 7B for 1.001T tokens. The 3B is competitive with GPT-Neo and Pythia-2.8B on HELM (+3–5 pts) and LM-eval-harness (+2–7 pts). The 7B trails Falcon-7B by 1.0 pt and Llama-7B by 4.1 pts on HELM-classic; we attribute the gap largely to the FP16 training requirement and to residual uncertainties in dataset reconstruction.

C4 / GitHub / Wikipedia / Books / ArXiv / Stack Exchange。C4 用 Allen AI 的 c4_en。GitHub 用 Google BigQuery 上 Apache/BSD/MIT 协议项目,用文件长度、字母数字比、扩展名等启发式过低质。Wikipedia 用 2023-03-20 dump。Books 只用 Gutenberg 的 PG19 子集(Books3 因版权问题撤回)。ArXiv 只保留 LaTeX 源,移除 preamble、注释、参考文献,并展开宏。Stack Exchange 取 28 个最大站点,移除 HTML 标签,按分数排序回答。

为评估 RedPajama-V1 对 LLaMA 语料的吻合度,我们与 Oak Ridge National Lab 合作,在 Summit 超级计算机(4608 节点,每节点 6×V100,IBM Power9 架构)上训练 RedPajama-INCITE 模型族(3B / 7B,base + instruction-tuned)。关键挑战:V100 不支持 bf16,我们必须用 fp16 + loss scaling,并把学习率压低($1.6\times10^{-4}$ for 3B、$1.2\times10^{-4}$ for 7B);7B 用 12-way pipeline 并行,3B 用 6-way,二者均加 2-way tensor 并行。3B 跑 800B tokens,7B 跑 1.001T tokens。3B 在 HELM 上比 GPT-Neo、Pythia-2.8B 高 3–5 分,在 LM-eval-harness 上高 2–7 分;7B 在 HELM-classic 上落后 Falcon-7B 1.0 分、落后 Llama-7B 4.1 分,差距主要来自 fp16 训练限制以及数据集复刻中的残余不确定性。

§4.1 RPv2 数据处理 · CCNet + 多语种p.6

In contrast to the first iteration, the second iteration of RedPajama focuses exclusively on web data and, in addition to the design principles Transparency and Scale, puts a higher emphasis on Versatility. Specifically, the purpose of the corpus is to serve as a foundation for creating high-quality subsets. While transparency is achieved by making the dataset and its artifacts publicly available, and scale by processing large parts of the Common Crawl corpus, we follow the design principle Versatility by releasing RedPajama-V2 as a dataset enriched with metadata that enables fast and cheap iteration for creating high-quality, diverse and large datasets.

与第一次迭代不同,RedPajama 的第二次迭代专注于 web 数据,并在透明度与规模原则之外,更强调多用途。具体而言,该语料的目的是充当构建高质量子集的基础。透明度通过公开数据集及其产物来达成;规模通过处理 Common Crawl 的大部分语料达成;多用途则通过为数据集附加一套元数据来实现——使下游能够低成本、快速地迭代出高质量、多样、大规模的数据集。

Data acquisition. The Common Crawl Archive is a vast, freely available repository of web crawl data, updated (bi-)monthly since 2013. Next to raw HTML (.warc), it provides metadata (.wat) and plain text (.wet). It has been the basis for numerous datasets including C4, RefinedWeb, Dolma and FineWeb. To create RedPajama-V2, we used the web-extracted text (.wet files) from all 84 monthly snapshots between 2014 and April 2023 and passed them through the CCNet pipeline. In contrast to RPv1, here we keep all perplexity buckets (head, middle and tail), and in addition to English, we also keep French, German, Italian and Spanish data. We chose this pipeline due to its light processing, which aligns with our guiding principle of preserving as much information in the raw dataset as possible and allowing downstream model developers to filter the dataset. This processing step produces over 100 billion individual text documents.

数据获取。Common Crawl Archive 是一个自 2013 年起免费公开、按(双)月更新的庞大网页爬取库。除原始 HTML(.warc)外,它还提供元数据(.wat)与纯文本(.wet)。它已是 C4、RefinedWeb、Dolma、FineWeb 等众多数据集的基础。为构建 RedPajama-V2,我们采用了 2014 至 2023 年 4 月间共 84 个月度 snapshot 的 .wet 文件,并通过 CCNet 流水线处理。与 RPv1 不同的是,这里我们保留全部困惑度桶(head / middle / tail);除英文外,还保留法语、德语、意大利语、西班牙语。选择该流水线是因为其处理轻量,符合"在原始数据集中尽量保留信息、让下游开发者自行过滤"的指导原则。此步骤产出超过 1000 亿(>100B) 篇文档。

§4.1.2 Quality Signals / 五类 40+ 信号p.7

A central ingredient to state-of-the-art open LLMs like Llama, Mistral, Falcon, MPT or the Qwen models is the large amount of high-quality data they are trained on; e.g., Llama 3 is trained on 15 trillion carefully curated tokens. The most prominent data sources at this scale are the crawls publicly available from CommonCrawl. However, even this CCNet-processed raw text is still not ideal for direct use as LLM training data, due to artifacts arising from HTML-to-plain-text conversion (parsing errors, menus), generally low-quality sources, and biases inherent to the web's content distribution. Unlike previous datasets that filter out low-quality content, our approach retains the entire raw text corpus, incorporating quality signals as additional metadata. This strategy uses the full spectrum of data, transforming sections typically discarded into informative attributes, and enables the creation of other datasets such as C4 as special cases of RedPajama-V2. For each document, we provide the quality signals used in C4, Gopher, RefinedWeb, the Pretrainer's Guide, and DSIR, which we group into five categories.

Llama、Mistral、Falcon、MPT、Qwen 等 SOTA 开源 LLM 的关键成分,是大量高质量数据(例如 Llama 3 在 15 万亿精挑细选的 tokens 上训练)。在此规模上最显著的数据源就是 CommonCrawl 公开的爬取。然而,即便经 CCNet 流水线处理过,这种原始文本仍不适合直接当 LLM 训练数据,原因有三:① HTML 转纯文本带来的人工痕迹(解析错误、菜单);② 整体低质的来源;③ web 内容分布的固有偏差。与以往"先过滤"的数据集不同,我们的方案保留整个原始语料,把 quality signals 作为额外元数据挂上去。这种策略让数据的全部光谱都可用——把通常被丢弃的部分转化为信息属性,并使 C4 等数据集成为 RedPajama-V2 的特例。我们为每篇文档提供 C4、Gopher、RefinedWeb、Pretrainer's Guide、DSIR 中使用过的 quality signals,大致分为五类。

① Natural Language. Text documents extracted from websites often contain content that is not natural language—JavaScript code, menus, boilerplate. To measure how "natural" a document is, we provide simple heuristics such as the fraction of all-caps words or letters, the fraction of lines ending with an ellipsis, the fraction of unique words, whether a line ends in a terminal punctuation mark, etc.

② Repetitiveness. Repetitive text is an often-observed web artifact, linked to uninformative content; repetitious generations are also a known failure mode of LMs, and removing excessively repetitive content can mitigate this behavior. For each document we calculate (a) the fraction of characters appearing in the most frequent (word) $n$-gram for $n\in\{2,3,4\}$, and (b) the fraction of characters appearing in any duplicated $n$-gram for $n\in\{5,\ldots,10\}$. We ensure not to count characters in overlapping $n$-grams more than once.

① 自然语言度(Natural Language)。web 抽取出来的文本常含非自然语言内容——JavaScript 代码、菜单、模板。为衡量"自然程度",我们提供简单启发式:全大写词或字母比例、行末省略号的行比例、unique-word 比例、行末是否为终止标点等。

② 重复度(Repetitiveness)。重复文本是 web 数据中常见的伪迹,与无信息内容相关;同时它也是 LM 已知的失效模式之一,移除过度重复内容可缓解该问题。对每篇文档我们计算 (a) 最高频(word)$n$-gram 字符占比($n\in\{2,3,4\}$);(b) 任意重复 $n$-gram 字符占比($n\in\{5,\ldots,10\}$)。我们确保重叠 $n$-gram 中的字符不重复计数。

③ Content-based. Web documents can contain harmful or offensive content. We provide the signals used in C4 and RefinedWeb: (1) the number of word sequences contained in the LDNOOBW blocklist, and (2) a flag indicating whether the document's domain appears in the UT1 list of blocked URLs. While these focus on NSFW content, other content-based filters such as domains or embedding clusters are also promising directions.

④ ML Heuristics. ML-based quality signals revolve around measuring similarity to a high-quality domain. We use fastText classifiers and the importance weights proposed in DSIR. While ML filters have been shown to improve dataset quality, they have also been reported to lead to biases or underrepresentation of minorities. Our fastText classifier signals are unigram bag-of-word models trained to distinguish unfiltered RPv2 data from a high-quality domain: for English, Wikipedia, websites referenced by Wikipedia, books, and OpenWebText; for non-English, only Wikipedia. The DSIR weights estimate the importance of individual samples relative to a target domain in a reduced feature space (word unigrams + bigrams), defined as the log-likelihood ratio between the target and source domain language models.

⑤ Deduplication. Removing duplicated training data has been found to improve model perplexity and reduce memorization while reducing training data size and required compute. In RPv2 we include MinHash signatures for fuzzy deduplication at different similarity levels, as well as IDs of documents found to be exact duplicates via a Bloom filter with the error rate set to 1%. We proceed sequentially, starting with the most recent dump (2023-14) and iterating to the oldest (2014-15). Exact deduplication was performed based on the hashes of the .wet documents (i.e., prior to processing with CCNet).

③ 内容(Content-based)。web 文档可能含有害 / 冒犯内容。我们提供 C4 与 RefinedWeb 使用过的两类信号:(1) 文档中命中 LDNOOBW 黑名单的词序列数;(2) 文档所属域名是否出现在 UT1 黑名单的标志。这两者主要针对 NSFW;域名或嵌入聚类等其他基于内容的过滤也是有前景的方向。

④ 机器学习启发式(ML Heuristics)。ML 类 quality signal 围绕"与高质域的相似度"展开。我们采用 fastText 分类器以及 DSIR 提出的 importance weight。已有工作表明 ML 滤镜能提升数据质量,但也会带来偏差或对少数群体的表征不足。本文的 fastText 分类器是一元 bag-of-word 模型,用于把"未过滤 RPv2"与"高质域"分开:英文目标域为 Wikipedia、Wiki 引用网站、books、OpenWebText;非英文只用 Wikipedia。DSIR 权重在降维特征空间(unigram + bigram 词模型)估计单个样本相对目标域的重要性,定义为"目标域语言模型 vs 源域语言模型"的对数似然比。

⑤ 去重(Deduplication)。去除重复训练数据可改善模型困惑度、降低记忆程度、同时压缩数据规模与算力消耗。RPv2 中提供:不同相似度阈值下的 MinHash 签名(模糊去重)+ 通过 Bloom filter(错误率 1%)找出的精确重复文档 ID。处理顺序为由新到旧:从最新的 2023-14 起,逐个 dump 直到最老的 2014-15。注意精确去重是基于 .wet 文档的哈希做的,在 CCNet 处理之前就完成。

§4.2 Dataset Statistics / 数据统计p.8

RPv2 consists of 113B documents in five languages: English, German, French, Spanish and Italian. As mentioned previously, the CCNet pipeline partitions the dataset into three buckets—"head", "middle", and "tail"—corresponding to documents with low, medium, and high Wikipedia perplexity. There are 32.8B documents in the head+middle partition and 80B documents in the tail partition. Documents in the tail are typically shorter (~850 tokens) than in the head and middle buckets (~1500 tokens). Token counts were estimated based on an i.i.d. sample of 100M documents using the Mistral BPE tokenizer.

Table 3 breaks tokens down by language and partition (head+middle deduplicated, T = trillion): English 20.5T (14.5B docs); German 3.0T (1.9B); French 2.7T (1.6B); Spanish 2.8T (1.8B); Italian 1.5T (0.9B); total 30.4T tokens / 20.8B docs. Adding the tail partition brings the raw totals to 113.3B documents / 123.7T tokens before deduplication.

§4.3 Dataset Ablations · Setup / 消融设置p.8

Here we present a series of dataset ablations aimed at understanding how the quality signals introduced above influence the downstream performance of language models trained on data filtered with different heuristics. More specifically, we ask: how do different quality-filtering rules affect downstream performance? We strive for a broad evaluation and measure performance on diverse downstream benchmarks and on the language-modeling objective in multiple domains.

本节给出一系列数据集消融,目的是搞清楚上文 quality signals 如何影响"用不同启发式过滤的数据"训出来的 LM 的下游性能。具体而言,我们要回答:不同 quality-filtering 规则如何影响下游性能? 我们追求广覆盖的评测:多样化下游 benchmark + 多个域上的语言建模目标。

Models. We adopt decoder-only Llama-2 architectures with 468M and 1.6B parameters and a 2048 sequence length. Both have 24 layers, 16 attention heads, MLP expansion ratio 4.0; the 468M uses 1024 hidden dim, the 1.6B uses 2048. For each dataset, we train the 468M on 100B tokens and the 1.6B on 350B tokens. We use AdamW with weight decay 0.1, peak learning rate $5\times10^{-3}$ and $5\times10^{-4}$ respectively, and a cosine decay schedule with linear warmup over the first 1% of steps. The relatively small scale lets us explore a wider range of filters, showing the breadth of quality filters available in RedPajama.

Hardware & training stack. We use the OLMo framework for distributed training with FSDP for parallelization across multiple GPUs and nodes; lm-evaluation-harness for evaluation; up to 5 H100 nodes with Infiniband interconnect.

Evaluation metrics. We aim for broad coverage of benchmarks and domains. Similar to FineWeb, we look for benchmarks providing a high enough signal-to-noise ratio at this small model scale. After careful consideration, our 11 aggregate benchmarks (Table 4) include ARC-e, Winogrande, Hellaswag, LAMBADA, CoQA, MMLU, OpenbookQA, PIQA, PubMedQA, SciQ. We report three aggregates: (1) the simple average across benchmarks, (2) a normalized average, and (3) the normalized sum of ranks; the latter avoids averaging across scores of different scales. To rank datasets by perplexity, we follow the Dolma approach and adopt the Paloma and Pile validation sets.

模型。采用 decoder-only Llama-2 架构,468M 与 1.6B 两档,序列长度 2048。二者都用 24 层、16 个注意力头、MLP 扩展比 4.0;468M 隐藏维 1024,1.6B 隐藏维 2048。每个数据集上,468M 训 100B tokens,1.6B 训 350B tokens。优化器 AdamW(weight decay 0.1),峰值学习率分别 $5\times10^{-3}$ 与 $5\times10^{-4}$;cosine 衰减 + 前 1% 线性 warmup。规模故意小,以便扫更多过滤组合,展示 RedPajama 中可用 quality filter 的广度。

硬件 & 训练栈。分布式训练用 OLMo 框架 + FSDP;评测用 lm-evaluation-harness;集群用最多 5 个 H100 节点 + Infiniband 互联。

评估指标。追求 benchmark 与域的广覆盖。与 FineWeb 类似,我们挑选在此小规模下信噪比足够高的 benchmark。最终聚合的 11 项 benchmark(表 4)包括 ARC-e、Winogrande、Hellaswag、LAMBADA、CoQA、MMLU、OpenbookQA、PIQA、PubMedQA、SciQ。报告三种聚合:(1) benchmark 简单平均;(2) 归一化平均;(3) 归一化 rank 之和——后者避免把不同 scale 的分数加在一起。对"按目标域 PPL 排数据集",我们沿用 Dolma 的做法,采用 Paloma 与 Pile 的验证集。

§4.3.2 Results / 过滤组合消融结果p.9

We start by using the quality signals to implement some of the most widely used filters in the literature. In addition, we also investigate ML heuristics available in RPv2, based on fastText bag-of-$n$-gram classifiers and DSIR importance weights. We run ablations on two subsets of RPv2: the 2023-14 crawl alone, and the 9 crawls from 2021-49 to 2023-14, which were deduplicated using MinHash LSH on word 13-grams, with 128 hash functions, 9 bands and 13 rows. For the 1.6B ablations, we filter the full RPv2 dataset, sample roughly 1T tokens, and deduplicate it with the same Minhash hyperparameters.

Filters. We seek to cover a wide range of quality-filtering configurations. Rather than optimizing performance on a particular benchmark, the goal is to show that filtering RPv2 in different ways can lead to wildly different model performance. We experiment with variations of the C4 and Gopher rules and also use the ML-based quality signals in RPv2. We also use a custom-rules configuration based on word counts, average line length, Wikipedia perplexity and the Wikipedia References classifier.

我们先用 quality signals 复现文献中最常见的几种过滤,然后再研究 RPv2 中的 ML 启发式——基于 fastText bag-of-$n$-gram 分类器与 DSIR importance weight。消融在两个 RPv2 子集上进行:① 单 dump 2023-14;② 从 2021-49 到 2023-14 共 9 个 dumps,后者用 MinHash LSH(word 13-gram,128 hash 函数,9 bands,13 rows)做模糊去重。1.6B 消融:先对全 RPv2 过滤,再采样约 1T tokens,用同一组 MinHash 超参去重。

过滤器。我们追求覆盖广泛的 quality filter 配置组合,目标不是在某个具体 benchmark 上调优,而是展示不同过滤方式可以训出表现差异巨大的模型。我们扫了 C4、Gopher 规则的多种变体,并使用 RPv2 中的 ML quality signal。我们还有一种定制(custom-rules)配置,基于词数、行平均长度、Wikipedia 困惑度与 Wikipedia References 分类器。

Results. From Table 5 we draw several conclusions on filtering the RedPajama-V2 dataset. First, the Gopher rules generally improve performance. In particular, fuzzy deduplication + Gopher has the highest aggregated scores across all RPv2 datasets; the average and normalized average benchmark scores are second only to RefinedWeb, while the rank-score is higher than RefinedWeb's. The per-benchmark tables in the Appendix show that RPv2 filtered with fuzzy dedup + Gopher is always in the upper middle (minimum rank score 9 of 19), while RefinedWeb performs worse on Hellaswag, LAMBADA, Winogrande, MMLU and OpenBookQA. This indicates that filtering RPv2 with the full Gopher rules and fuzzy deduplication (Minhash LSH) creates a dataset that performs well across a wider range of tasks than all other datasets.

Second, the Gopher-natlang filters perform better than the Gopher-repetition filters. Third, in the context of model-based filtering, we see no significant difference between using a fastText classifier and DSIR. Fourth, using only the line-level C4 filters appears to reduce perplexity but has negligible effect on the aggregated benchmark scores. Finally, we notice that the unfiltered RPv2 2023-14 dataset appears to have the lowest perplexity on the Paloma dataset, while other filtering methods lead to models with higher perplexity. We believe this can (at least in part) be attributed to the wide range of domains covered by Paloma. In addition, Paloma also contains the RPv1 dataset, which can explain the low perplexity score obtained by the model trained on RPv1-CC. Table 6 further shows that the model trained on RPv2 filtered with the full Gopher rules outperforms the model trained on RPv2 filtered with only the Gopher-natlang rules, and comes close to the quality of a model trained on the RefinedWeb dataset. In conclusion, this series of ablation studies shows how the quality signals in the RPv2 dataset can be used to successively filter better datasets. In combination with its vast scale of over 100T tokens, RPv2 provides a powerful source for creating high-quality web datasets for LLM pretraining.

结论。从表 5 可以得出关于过滤 RedPajama-V2 的若干结论。第一,Gopher 规则普遍提升性能;特别地,fuzzy 去重 + Gopher 在所有 RPv2 数据集中聚合分最高;平均与归一化平均 benchmark 分仅次于 RefinedWeb,但 rank-score 反超。附录里逐 benchmark 的表显示:fuzzy 去重 + Gopher 过滤后的 RPv2 始终位于中上(rank-score 最低 9/19),而 RefinedWeb 在 Hellaswag、LAMBADA、Winogrande、MMLU、OpenBookQA 上更弱。这说明用完整 Gopher + MinHash LSH 模糊去重过滤的 RPv2,在更广任务面上的表现优于其他数据集。

第二,Gopher-natlang(自然语言度)滤镜比 Gopher-repetition(重复度)更好用。第三,在模型类过滤中,fastText 与 DSIR 差距不显著。第四,仅用 C4 line-level 过滤能降 PPL,但对聚合 benchmark 分几乎无影响。最后,我们注意到未过滤的 RPv2 2023-14 在 Paloma 上 PPL 最低,而过滤方法反而使 PPL 升高;我们认为这至少部分源于 Paloma 域分布很广。此外 Paloma 还包含 RPv1 数据,这也能解释为何在 RPv1-CC 上训的模型 PPL 偏低。表 6 进一步表明:用完整 Gopher 规则过滤的 RPv2 训出来的模型,优于只用 Gopher-natlang 训出来的模型,且接近用 RefinedWeb 训出来的模型质量。总之,这一系列消融展示了 RPv2 的 quality signals 可以被层层用来过滤出更好的数据集;结合其 100T+ tokens 的庞大体量,RPv2 是构建 LLM 高质量 web 预训练数据集的强大基础。

§5 Conclusion / 结论p.10

In this paper, we have presented the RedPajama datasets. With over 100 trillion tokens, these are the largest, fully open and transparent datasets for pretraining language models, and have been a central building block for many of the strongest open-source LLMs. Next to documentation accompanying the datasets, we have also shown examples of how RedPajama-V2 can be filtered down to successively higher-quality subsets, leading to language models of varying levels of quality on a diverse set of benchmark tasks and outperforming models trained on other large-scale pretraining corpora.

本文呈现了 RedPajama 数据集。合计超过 100 万亿 tokens,它们是目前最大的、完全开放且透明的语言模型预训练数据集,也已成为众多最强开源 LLM 的核心构件。除了配套文档外,我们还展示了 RedPajama-V2 如何被逐步过滤为更高质量的子集——训出在多样化 benchmark 上表现层次分明的语言模型,且优于在其他大规模预训练语料上训出的模型。

Limitations. While the models are relatively small and enabled us to explore a wider variety of filters, this is also a limitation, and further, larger-scale explorations are required. We did not explore a thorough decontamination analysis against common benchmarks or an analysis of personally identifiable information present in the dataset, posing another limitation of this work. By publishing the RedPajama-V2 dataset in raw, unfiltered form, but accompanied by a set of quality signals, we hope that future work will continue to build on RedPajama and provide new innovative ways of filtering, curating, and mixing multiple pretraining corpora.

局限。模型相对较小,这一方面让我们能扫更多过滤器,另一方面也是一个局限——需要更大规模的进一步探索。此外,我们没有对常见 benchmark 做彻底的去污染分析,也没有分析数据集中可能存在的个人身份信息(PII),这是本工作的另一局限。通过以"原始未过滤 + quality signals"的形式发布 RedPajama-V2,我们希望未来工作能继续在 RedPajama 之上,提出过滤、整理与混合多源预训练语料的创新方法。

Due to their differing nature, the two datasets are structured differently. B.1.1 RedPajama-V1 RedPajama-V1 consists of seven domains and is structured accordingly. Except for the Common Crawl subset, each component follows the structure { "text": "...", "meta": {...} } The meta field varies between the different sources: • The Arxiv subset has the meta fields timestamp, yymm, arxiv_id, language and url. • The C4 subset has the meta fields timestamp, source, language and url. • The Github subset has the meta fields content_hash, timestamp, source, line_count, max_line_length, avg_line_length, alnum_prop, repo_name, id, size, binary, copies, ref, path, mode, license, language. • The Stack Exchange subset has the meta fields timestamp, source, language, question_score and url. • The Wikipedia subset has the meta fields timestamp, title, language, and url. The Common Crawl subset follows the structure { "text": "...", 16 "pred_label": ..., " pred_label_prob ": ..., "wiki_prob": ..., "source": "..." } B.1.2 RedPajama-V2 The core of the dataset is composed of the text documents, accompanied by the quality annotations, duplicate ids and minhash signatures. For the text documents, the structure largely follows the one defined by CCNet. Specifically, the documents for a given CommonCrawl snapshot are partitioned into 5000 shards, where the filename indicates the shard, language of the document, and the perplexity bucket (partition). The quality annotations, duplicates and minhashes follow the same logic and reflect the filenames of the raw documents. File Structure. The files containing the raw text documents are organized according to the following pattern: documents/<snapshot_id>/<shard_id>/<lang>_<ppl_bucket>.json.gz where snapshot_id corresponds to any of the crawls included in RPv2, shard_id ranges from 0000 to 4999, lang is any one of en, de, fr, es or it. Finally, ppl_bucket indicates the partitioning according to Wikipedia perplexity and is either head, middle or tail. Similarly, quality signals, duplicate ids and minhashes follow the patterns quality_signals/<snapshot_id>/<shard_id>/<lang>_<ppl_bucket>.signals.json.gz, duplicates/<snapshot_id>/<shard_id>/<lang>_<ppl_bucket>.duplicates.parquet, and minhashes/<snapshot_id>/<shard_id>/<lang>_<ppl_bucket>.minhash.parquet. Documents Structure. The documents are stored as Gzip-compressed JSONL files and follow the schema { "url": "...", "date_download": "...", "digest": "...", "length": ..., "nlines": ..., "source_domain": "...", "title": "...", "raw_content": "...", "cc_segment": "...", " original_nlines ": ..., " original_length ": .., "line_ids": [...], "language": "...", "language_score": ..., "perplexity": ..., "bucket": "..." } Quality Signals Structure. The quality signals are Gzip-compressed JSONL files and follow the schema { "id": "...", "id_int": ..., "metadata": { "cc_segment": "...", 17 "cc_net_source": "...", "url": "...", "source_domain": "...", "language": "...", "snapshot_id": "..." }, " quality_signals ": { "key": [[start, end, score]] } } The quality_signals field is a dictionary with the name of the quality signal as key and a list of tuples as values. Each tuple consists of the three floats start, end, and score indicating the location where the score in the raw_content string applies. This representation follows the one used in Dolma [52] and allows a single representation to encode quality signals which apply at different levels of granularity of the text (e.g., line-level and document-level). Duplicate IDs. The ids of duplicated documents are stored as parquet files. Each row in the parquet file corresponds to a document which is duplicated at least once across the entire corpus. We emphasize that this does not include the first occurrence of a document which has subsequent duplicates. In other words, if every document appearing in the list of duplicates is dropped, one member of each cluster of documents remains in the dataset. Minhashes. The minhash signatures are stored in parquet files and are partitioned into multiple bands and rows, corresponding to different levels of Jaccard similarities in the range {0.7, 0.8, 0.9, 1.0}.
